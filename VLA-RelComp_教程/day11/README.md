# Day 11：最小反事实与匹配配对

## 当日目标，以及为什么服务于 VLA-RelComp

设计 2–3 组配对：尽量固定场景、对象集合、初始状态、seed、模型和推理设置，只改变一个有效空间关系或对象组合。它让行为翻转更可能归因于组合变化，而不是场景/随机性。

## 前置知识和开始前自检

已有 task manifest 与阶段定义。自检：只改英文指令但环境 goal 不变算新任务吗？两项现成 L0/L1 场景看起来相似就一定匹配吗？

## 具体场景与最小例子

基准要求将同一番茄放在 A 碗上；反事实要求放在 B 碗上。若只是改文字而 BDDL goal 仍检查 A，标签不同步，pair 无效。若 B 碗位置也改变，至少有关系/参照/几何多个变化，不能称最小。

## 零基础知识讲义

反事实问“若只改变 X，结果会怎样”。真实实验很难绝对只变一项，因此用匹配与明确残余差异提高可解释性。Pair 是分析单位；两条件用相同 seed/init，记录 `both_success`、仅 A 成功、仅 B 成功、均失败。

CBDDL 现有 L0/L1 任务未必天然形成严格 pair。自定义 pair 必须预登记、goal 同步、可达性验证、人工回放，不能根据模型输出临时修改。新 task 不能把正确对象标记直接暴露给最终策略。

## 操作步骤、状态与预期输出

`待用户执行`：复制 pair 模板，填 2–3 对，每对两行，`changed_factor` 只写一项；列出所有固定项。`静态核验`：goal 与 instruction 必须同步、对象实例存在。`实测`：用 CSV 标准库检查每个 pair 恰两条件且 seed/init 相同（可先人工+短脚本）。`估计—未运行`：仿真可达和回放尚未验证。

变量实验：故意让第二条件 seed 不同，检查应失败；修正后再通过。预期输出是结构验证，不是 pair 具备因果有效性的最终证明。

## 在真实代码中的位置

自定义 BDDL/配置放项目 `manifests`/`configs`，不直接覆盖官方文件；goal 由 BDDL evaluator；init 用明确索引。结果 registry 含 `pair_id` 或可由 manifest 连接。

## 常见错误、诊断顺序、备用路线与止损

先列变化项，超过一项就降级为普通比较；再核 goal；再核 init/state；最后回放可达。单 pair 设计 90 分钟止损。若无严格 pair，可报告近似匹配与残余差异，不伪称最小；若所有 pair 无效，Gate 3 退出条件可能触发。

## 时间预算、最低完成线、标准完成线与选做

正常 6–8 小时。最低：两对完整 manifest、每对一个变化。标准：goal/泄漏/可达核验计划齐全。选做：画 DAG 列出场景变化到 success 的替代路径。

## 当日交付物

pair manifest、固定变量表、无效 pair 反例、泄漏检查、2 分钟口述。

## 自测题、参考答案与复试口述

问题：为什么改指令还要改 goal？为什么同 seed 不够？何时称近似匹配？能否看失败后换容易位置？pair 分析单位是什么？

参考答案：确保标签语义一致；场景资产/初态等仍可不同；存在已披露残余差异；不能，会选择性偏差；成对条件结果。复试口述要说明控制变量与不可消除替代解释。
