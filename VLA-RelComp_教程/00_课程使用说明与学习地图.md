# 课程使用说明与学习地图

> 受众：零科研基础，但有 408/C 基础并接触过少量 Python、Linux 和 Git。真正零编程基础者先完成 `assets/零编程基础前置轨说明.md` 的就绪检查；前置轨不是 Day 0—14 的第二套课程。

## 一条主线

课程始终追踪同一问题：模型为何能在训练组合上做、换成未见对象—空间关系组合后失败？学习顺序不是“先学完整 AI”，而是每学一个概念就在目标代码、数据或小实验中看到它。

```text
Day 0 证据与工具
  → Day 1–4 输入—动作—环境—success 最小闭环 / Gate 1
  → Day 5–8 分布、统计与可分析模型 / Gate 2
  → Day 9–14 BDDL、阶段链、反事实、oracle、泄漏 / Gate 3
```

每个概念遵循：为什么现在需要 → 定义 → 直观例子 → 必要原理 → 官方表示 → 最小实验 → 改一个变量 → 连接研究问题 → 自测/交付。

## 每日执行法

把约 8 小时分成认知、跟做、独立改动、记录和脱离 Agent 口述。任务块 25–90 分钟；达到当日止损就保存错误和上下文，按备用路线继续。没有证据文件不算完成；Agent 做完但本人不能复述也不算完成。

最低完成线保证次日能继续；标准完成线才计入 Gate。提前完成只做当日选做，不扩第二个 suite，不学 RLHF/PPO/GRPO/ROS/真机标定/多机训练。

Every-Embodied 等社区资料只收在 `assets/按需参考索引.md`：不是前 14 天必读，不计入每日时间，不带来新环境或安装任务。遇到某个概念仍不直观时才按问题查一项；任何事实与命令仍回到官方论文、冻结代码和协议核验。

## 研究与教学的边界

教程 fixture 的 id 均以 `fixture_` 开头，它们只验证代码与概念。论文数字必须标论文结果；GPU/仿真未跑项必须标未运行。最终项目只根据真实、版本化、任务级 episode 证据下结论。

## 请求帮助时提供什么

提供当前 Day、目标、从哪一目录执行的完整命令、完整 traceback/退出码、环境探针、相关配置副本、最后一个成功步骤和已用排错时间。删除 token 后再分享；不要只发“报错了”。

## 硬暂停与普通故障

付费/租用、凭据、新权限、单项>20GB、可能覆盖原始数据或公开仓库、重大官方变化、直接撞题、必读冲突才暂停询问。路径、依赖、链接变化、普通安装/测试错误继续有边界排查。状态最终不可观测、pair 无效或结果不可重复是在正式 Gate 3 形成证据后触发 D1，不由当前 Mac 预判。
