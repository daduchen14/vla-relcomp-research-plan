# Day 8：统一 pilot、模型选择与 Gate 2

## 当日目标，以及为什么服务于 VLA-RelComp

把 5 tasks×3 levels×5 trials 的 pilot 写成统一 registry 和决策规则，完成 Gate 2 模板。目标是选择可分析的主模型，不做模型排名。

## 前置知识和开始前自检

完成 Day 5–7。自检：75 行从何而来？D1 暂定的 L0 门槛是多少？异常 episode 能否偷偷删掉？

## 具体场景与最小例子

SmolVLA L0 6/25、OpenVLA L0 10/25：在其他工程条件合格时，前者未过暂定 8/25，后者可作主诊断候选。这个数值只是决策例子，不是实验结果。

## 零基础知识讲义

Pilot 是小规模可行性与方差探测，不是最终基线。统一协议要求模型外的任务、trial、seed/init 策略、异常分类和汇总方法相同。Gate 2 同时看 L0 样本、吞吐是否适配 70 天、失败是否源于工程异常、用户能否解释三类失败。

模型选择规则必须在看结果前写。若 SmolVLA 未过而 OpenVLA 过，诊断用 OpenVLA；训练角色另定。若所有官方模型无可分析 L0 能力，才触发 D1 退出，不继续堆 GPU。

## 操作步骤、状态与预期输出

`实测`：运行 registry 验证器确认 fixture schema。`待用户执行`：在获批 GPU 环境为每模型生成预登记 75 行空 registry，按 episode 写入，不事后重排行。`静态核验`：配置存在 trials/seed/init/result/log/video 字段。`估计—未运行`：用真实单 episode 墙钟乘计划量并加启动/失败缓冲，当前不得填假数字。

Gate 2 表必须输出：模型、L0 k/25+CI、L1/L2计数、异常率、每 episode 中位墙钟、峰值显存、预计全评测时间、通过/不通过、理由。原始任务级表优先于宏平均。

## 在真实代码中的位置

官方 evaluator 聚合结果；项目 `episode_registry.csv` 保存每行证据；Gate 表放 `notes/gates/gate2.md`。配置注册名固定，replacement 关闭。

## 常见错误、诊断顺序、备用路线与止损

75 行不完整先查 task×level×trial 唯一键；异常过多先修基础设施；仅看总成功率回到任务级；看完结果后改门槛必须记 post hoc。数据整理止损 60 分钟，模型工程故障按 Gate 1 路径处理。

## 时间预算、最低完成线、标准完成线与选做

正常 6–8 小时。最低：生成完整空 registry 与 Gate 表。标准：能用假想数据按冻结规则得出唯一选择并解释不确定性。选做：写程序检查 75 个唯一键。

## 自测题、参考答案与复试口述

问题：pilot 等于最终基线吗？门槛能否看结果后调？为何记录任务级？若 Smol 失败 OpenVLA 通过怎么办？何时切备用？

参考答案：不等于；不能静默调；防止平均掩盖；OpenVLA 主诊断、轻量训练另议；所有官方模型均无 L0 能力或其他 D1 硬条件失败。复试口述：模型选择是研究可识别性决策，不是排行榜。
