# Day 14：数据泄漏、Gate 3 与三分钟答辩

## 当日目标，以及为什么服务于 VLA-RelComp

完成研究切口闸门：审计 L1/L2、oracle 真值、post hoc 假设和测试初态；依据证据只写三种合法结论之一；用三分钟讲清问题—假设—实验—证据—边界。

## 前置知识和开始前自检

已有 Gate 1/2、task/pair manifest、阶段定义、oracle spec 和统计表。自检：pilot 看过 L1/L2 后还能否把同一批当最终盲测？负修复结果是否等于项目失败？“偶尔恢复一次”能否过 Gate 3？

## 具体场景与最小例子

研究者看了 L1 失败后选择最有效的 prompt，再在同一 L1 报“泛化提升”。即使没做梯度训练，也已用测试反馈调方法，发生泄漏。合法做法：预登记极小 pilot 的用途，冻结方法后另留未使用 init states 作为最终测试，并把新假设标 post hoc。

## 零基础知识讲义

数据泄漏是测试信息影响训练、样本选择、超参、早停或方法设计。L1/L2 pilot 可验证研究切口，但被看过部分不能继续冒充最终盲测。Oracle 真值可用于诊断，必须隔离于最终方法输入。

Pre-registration 是运行前固定假设、任务/seed/init、指标、排除、分析和门槛；post hoc 不是坏事，但要如实标注并在新数据验证。消融是在方法已定后移除/替换组件检查作用；对照是比较基准条件。

Gate 3 只允许：通过；诊断通过、修复暂缓；退出。通过要求可重复阶段差异和至少一种稳定恢复；安装完成、好看视频、单次偶然成功均无效。修复不涨点仍可保留可信失败分解、受控干预和边界。

## 操作步骤、状态与预期输出

1. `待用户执行`：逐项列出 L1/L2 哪些 task/init 已看、用于什么；划分最终未见测试。
2. `静态核验`：检查 final method 输入没有对象 id、真值框、goal 解析答案；oracle 与 method 结果分栏。
3. `实测`：复制 Gate 3 模板，用 fixture 练习决策；因为 fixture 非真实结果，合法结论只能写“教程分析链验证，不进行研究 Gate 判定”。
4. `估计—未运行`：正式 Gate 3 需批准 Linux/NVIDIA 的真实 pair/oracle 至少两 seed；当前不能勾通过。
5. 关掉材料，录三分钟：第一分钟问题/已知边界，第二分钟匹配反事实+四段+oracle，第三分钟证据/决定/不能推出。

预期 Gate 文档必须链接原始 registry/配置/commit，给唯一结论和反例；没有数据就留空，不用计划输出填数。

## 在真实代码中的位置

训练 dataset/config 必须仅 L0；L1/L2 registry 标用途；oracle 输入字段与 `src/interventions` 隔离；最终结果表含 L0 保持、L1/L2 盲测、seed 和消融。Gate 文档放 `notes/gates/gate3.md`。

## 常见错误、诊断顺序、备用路线与止损

先审数据用途，再审输入字段，再审选择/早停，再审结果措辞。发现泄漏时不删除历史：标记污染集并另留测试。Gate 写作止损 90 分钟；若真实状态不可观测、pair 无效、不可重复或直接撞题，按 D1 退出并请求执行备用，不自行改方向。

## 时间预算、最低完成线、标准完成线与选做

正常 6–8 小时。最低：完整泄漏清单、合法 Gate 模板、三分钟稿。标准：脱离 Agent 口述并回答十问，所有证据可回溯。选做：让同伴只看证据复核结论。

## 自测题、参考答案与复试口述

问题：看过 L1 后如何处理？oracle 真值能否训练最终法？post hoc 可否报告？修复无效还剩什么？哪些硬证据退出？

参考答案：标记 pilot/污染并另留盲测；不能；可以但必须标注并新数据验证；可信诊断、反事实、干预和失败边界；状态不可得、pair 无效、不可重复、墙钟超70天或直接撞题等 D1 条件。

复试口述问题：oracle 恢复能证明什么、不能证明什么？必须答“受控干预在当前条件下改善行为，支持该信息环节是限制之一；不能唯一证明内部表示、普遍机制或最终部署有效”。
